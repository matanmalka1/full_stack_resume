# Frontend — משימות פתוחות

המסמך כולל רק משימות שטרם בוצעו. משימות שהושלמו והיסטוריית המימוש הוסרו.

## דורש החלטת מוצר

- [ ] **אישור עובדה ללא שימוש מיידי** — להחליט אם לחשוף את
      `POST /facts/{id}/confirm`, כך שאפשר יהיה לאשר עובדה בלי להכניס אותה מיד
      לטיוטה. ייתכן שהחיבור הקיים בין אישור לשימוש הוא מכוון.

- [ ] **ניהול ארטיפקטים** — להחליט אם לפתוח פיצ'ר נפרד להצגת כל גרסאות ה־HTML/PDF,
      צפייה במטא־דאטה והורדה עם אימות שלמות. היכולות הקיימות בשרת:
      `GET /applications/{id}/artifacts`, `GET /artifacts/{id}` ו־
      `GET /artifacts/{id}/download`.

## נבחנו ונסגרו

- [x] **עדכון מודעת משרה במועמדות קיימת** — מומש. `POST /applications/{id}/job-snapshots`
      נחשף במסך ההכנה (`JobPostingUpdate`), בכל שלב ובלי לפתוח מועמדות חדשה. התצלום הקודם
      נשמר, וההשלכות — ניתוח שאינו פעיל עוד וטיוטה לא מעודכנת — נשארות תשובת ההיטל.

- [x] **היסטוריית עובדה בודדת** — אין מה לממש. `GET /facts/{id}` מחזיר את אותם
      `events` בדיוק שמחזיר `GET /facts/{id}/history`, והם כבר מוצגים ב־`FactLifecyclePanel`.
      חיווט הנתיב הנפרד היה בקשה שנייה לאותו מידע.

- [x] **רשומת החלטה ברמת המועמדות** — אין צורך במסך. רשומת החלטה נכתבת רק באישור גרסה,
      ולכן היא תמיד קשורה לגרסה מאושרת; `GET /applications/{id}/decision` מחזיר את האחרונה
      שבהן, ואת תוכנה `decision-markdown` כבר מציג במלואו ובנוסח קריא במסך הגרסה.

## סדר עבודה מוצע

1. להכריע אם אישור עובדה ללא שימוש הוא חלק מהמוצר.
2. להכריע אם ניהול ארטיפקטים נפתח כפיצ'ר נפרד.
