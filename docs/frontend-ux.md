### UX-09 - ממומש;

ב־[`JobPostingUpdate`](../../frontend/src/features/applications/components/JobPostingUpdate.tsx) קיימים ולידציית URL משותפת, מניעת שליחה ללא שינוי בטקסט ובכתובת, שליחת טקסט המשרה ללא `trim`, הסבר על יצירת תצלום חדש ושמירת הקודם, ושימור הקלט והצגת שגיאה בכשל שמירה.

**תרחישי קבלה שהרצתם לא אומתה:** URL תקין, שגוי וריק; ללא שינוי; שינוי URL בלבד; שינוי טקסט בלבד, כולל רווחים; כשל שרת ורענון הקשר.

## שאלה פתוחה מסקירת הקוד

**חלון מפתחות ה־idempotency.** ארבעת המפתחות הומרו מ־`useMemo(() => crypto.randomUUID(), [deps])`
למפתחות נגזרים דטרמיניסטית, כי React אינו מתחייב לשמר `useMemo` ואובדן cache היה
מייצר מפתח חדש. התוצאה: ניסיון חוזר אחרי כשל *קבוע* מחזיר תשובה שמורה במקום להריץ
מחדש. יש לאשר מול [state-and-use-cases §13](../spec/state-and-use-cases.md) שזו
ההתנהגות הרצויה, או לגזור את המפתח גם מזהות הניסיון. שאר ממצאי הסקירה בוצעו.

## כללי עבודה וסגירה

- **P1 — עדיפות גבוהה:** תהליך הכנת קורות החיים ושימוש יומיומי במסמך.
- **P2 — שיפור:** נוחות, חיפוש ואחידות ממשק.
- **P0 — חסם תהליך:** דרך מפורשת לפתרון החלטות שחוסמות אישור; יש לטפל לפני שיפורי נוחות.
- לפני מימוש מאמתים את הפער בקוד ובתרחיש שימוש. אם הוא כבר מכוסה, מתעדים את הכיסוי וסוגרים בלי לממש מחדש.
- הרשימה אינה אישור לשינוי חוזי המוצר. שינוי בזרימה, בהרשאות או במשמעות מצב חייב להתאים למפרט; סתירה לא פתורה היא חסם.
- React פונה ל־FastAPI; לוגיקת שימוש והרשאות נשארת בשכבת היישום. ה־API אינו מתחיל עבודת רקע בעצמו.
- אין לשנות או לדרוס עובדות, JobSnapshot, גרסה מאושרת, ארטיפקט או רשומת הגשה קיימים במסגרת שיפורי UX.

### UX-08 — הרחבת החיפוש הגלובלי

- [ ] **השלמת המשימה**

**מטרה:** להגיע לתוצאות שמעבר למעבר המהיר ולברר הרחבה לעובדות ולטיוטות היסטוריות.

**מצב קיים:** `GlobalSearchDialog` מחפש מועמדויות דרך השרת ומבקש עד שמונה תוצאות. חיפוש ריק מציג „דורש טיפול”. הסרת `limit: 8` לבדה אינה מבטיחה גישה לכל התוצאות.

**אזורי עבודה:** `GlobalSearchDialog`, רשימת המועמדויות ושאילתות API קיימות; חוזים נוספים רק אם נדרשים.

**צעדים לביצוע:**

- לשמור רשימת מעבר מהיר מוגבלת ולהוסיף „כל התוצאות”, עם העברת המונח לרשימה שתומכת בדפדוף תוצאות.
- לבדוק שאילתות לחיפוש עובדות והיסטוריה. אם חסרות, להגדיר חוזה יישום ו־API לפני הרחבת הממשק.
- להציג סוג תוצאה והקשר ולקשר למזהה המדויק, בלי להחליף רשומה היסטורית בגרסה האחרונה.
- לטפל בטעינה, אין תוצאות וכישלון ולשמר ניווט במקלדת והתנהגות חיפוש ריק.
- לכבד החרגת רשומות מחוקות מחיפוש ברירת המחדל.

**תנאי סיום:** יותר משמונה התאמות נגישות דרך „כל התוצאות”. בהרחבה לעובדות ולהיסטוריה, כל סוג מסומן ומוביל לרשומה הנכונה דרך ה־API.

**אימות למסירה:** יותר משמונה תוצאות, שימור מונח, עברית ואנגלית, רשומות מחוקות ומקלדת. הרחבת חתימה ציבורית או projection מחייבת גם pipeline דטרמיניסטי ללא AI.

### UX-17 — היסטוריית גרסאות מאושרות והשוואת תוכן

- [ ] **השלמת המשימה**

**מטרה:** לעבור בין גרסאות של אותה מועמדות, להשוות נוסחים ולזהות את הגרסה והקובץ שנמסרו בכל הגשה.

**מצב קיים:** `RevisionPage` פונה לגרסה מפורשת דרך ה־URL ומציג אותה. אין בו בורר גרסאות; צריך לבדוק אילו נתוני היסטוריה והגשה זמינים כבר בשאילתות.

**אזורי עבודה:** `RevisionPage`, `RevisionSummary`, שאילתות revisions ומועמדות, היסטוריית Submission וקישורי הורדת PDF.

**צעדים לביצוע:**

- להוסיף בורר גרסאות מאושרות עם תאריך אישור, מצב כשירות וסימון הגרסה המוצגת.
- לבצע מעבר באמצעות ה־URL של המזהה הנבחר, כדי שקישור ישיר ורענון ישמרו את הבחירה.
- להציג סימון הגשה רק מתוך רשומות Submission, עם קישור לגרסה ולארטיפקט המדויקים. הגשה חיצונית אינה הוכחה לגרסה פנימית.
- לאפשר בחירת שתי גרסאות להשוואת טקסט, תוך הפרדה משינויי נוסח המשרה שב־UX-13.
- לשמר אזהרות הקשר היסטורי ולוודא שהורדה או הגשה מתייחסות לגרסה המוצגת ולכשירותה, בלי להחליף אותה אוטומטית בחדשה ביותר.

**תנאי סיום:** כל גרסה מאושרת זמינה ניתנת לפתיחה ולהשוואה. אפשר לזהות מה נמסר בכל הגשה מתועדת; מידע שלא נרשם נשאר חסר. המעבר אינו משנה גרסאות, ארטיפקטים או היסטוריית הגשות.

**אימות למסירה:** גרסה יחידה, כמה גרסאות, Ready היסטורי, גרסה ללא PDF כשיר, כמה הגשות והגשה חיצונית. להתחיל מ־`RevisionPage.test.tsx`; שינוי projection או חתימת API מחייב pipeline ללא AI, ושינוי נתיב artifact מחייב golden ודפדפן.
